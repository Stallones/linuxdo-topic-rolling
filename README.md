# linuxdo-topic-rolling

为 linux.do 写的 Tampermonkey 油猴脚本（`linuxdo-bot.user.js`），用途只有一个：自动浏览论坛话题、规避重复，把帖子刷起来。目标单纯、效率优先，不带任何多余功能。

只碰“待阅”话题行，绝不盲目全表乱点：新话题蓝点、新回复未读徽章才是干活对象，点开真的阅读、等服务器把标记销掉，再开下一个。

## 功能特性

### 双角色协作，靠 localStorage 通信
同一脚本在不同页面扮演两种角色，页面间通过 `localStorage`（键前缀 `ldbot:`）协作：

- **调度者（list-dispatcher）**：运行在三个列表页之一。负责挑选“待阅”行、轮换列表 URL、用 `GM_openInTab` 打开/关闭话题标签、回列表后确认蓝点消失。
- **打工者（topic-worker）**：运行在被打开的话题页 `/t/topic/<id>`。当 `pending` 令牌命中自己时：等帖子数据加载 → 前台下滑固定距离并停留，让 Discourse 记录已读 → 完成后清令牌。

**手动打开的话题不受影响**：worker 只有在 `pending` 匹配当前话题 id 时才干活，否则直接退出、不自关标签。

### 只处理“待阅”行
列表行上按以下判据识别待阅内容，其余一概不动：
- 新话题蓝点：行带 `tr.unseen-topic`，即 `.topic-post-badges` 内的 `.new-topic`；
- 新回复未读徽章：`.topic-post-badges .unread-posts`（如“N 个未读帖子”）。

### 一次“阅读”的完整流程
1. 把候选话题行**滚动到视口正中**（能直观看到当前进度）；
2. `GM_openInTab(url, { active: true })` 打开新标签并**切到前台**；
3. worker 等待帖子流加载（帖子数连续 `READY_STABLE_MS` 稳定即视为就绪），前台下滑固定距离、停留约 3s，让阅读心跳上报；
4. 调度者**关闭话题标签**，焦点回到列表；
5. 等待蓝点消失（先给 1.2s 同步时间，最长 `DOT_WAIT_MS`）；
6. 保证与上一次打开的间隔 ≥ 面板设定的间隔（默认 10s），再开下一个。

### 列表循环，不重复进入同一话题
每个话题**每轮只进一次**：打开、下滑固定距离读一段、关闭，立刻浏览下一个，绝不对同一话题反复重试。读完这一话题后就把它放进本会话的“已处理”集合，**本次 url 会话内不再进入**；等列表里所有带标记的话题都过一遍（列表到底），再切到下一个 url，页面刷新后“已处理”集合清空，回来重新处理——此时有新回复的话题会再次带标记，属系统正常逻辑。只有“打不开标签”才记入跳过。

### 三列表轮换 + 空刷判定 + 无内容休眠
- 在 `/latest` → `/new` → `/unseen` 三个列表间**每 10 分钟自动轮换**；
- 当前页没有待阅行时，先**滑到底触发增量加载**，看是否带出新蓝点；
- 连续空刷达到阈值即判定“无内容”：`/new` 为 **1 次**，`/latest`、`/unseen` 为 **5 次**；
- 达到阈值进入**无内容休眠**：暂停扫描 5 分钟，面板显示橙色倒计时，期间可点“开始/取消休眠”立即恢复；倒计时到期自动切换到下一个列表。

### 控制面板
注入 Shadow DOM 右下角悬浮面板，实时显示：
- 当前列表 / 距下次轮换倒计时；
- 本会话**成功**（蓝点消失）与**跳过**计数；
- 开话题**间隔(秒)**输入框（改完即时生效并持久化）；
- **无内容休眠**剩余倒计时行；
- 底部单行状态日志。

按钮：**开始/暂停**（休眠中点按钮 = 取消休眠）、**自检**、**重置**。另通过 `GM_registerMenuCommand` 注册油猴菜单命令：开始、暂停、自检。

### 拟人化与稳健性
- **拟人滚动**：下滑分段执行，步长 `160~380px`、延迟随机；后台标签时步长加快，避免被浏览器节流拖慢；
- **兜底闭环**：worker 无论成败都清令牌并尝试 `window.close()` 自关；调度者侧即使 worker 没有回报，`FALLBACK_HOLD_MS`（10s）到点也强制关标签回列表，不会无限空等；
- **防多标签冲突**：列表页“页主”争夺，心跳 10s 续约，被其它列表页接管时本页自动让位，`beforeunload` 时释放占用；
- 注入即自动开始（`AUTO_START`），无内容会自己睡，无需值守。

## 使用方法
1. 在 Tampermonkey 中新建脚本，粘贴 `linuxdo-bot.user.js` 内容保存；
2. 打开 `https://linux.do/` 任意一个列表页（`/latest`、`/new`、`/unseen`）；
3. 无需手动操作，脚本自动开始扫描（或点面板/油猴菜单里的“开始”）；
4. 想歇就点“暂停”，随时可再开。

## 可调参数

面板上可直接调**开话题间隔**；其余参数位于脚本顶部 `CFG` 常量，改完重新加载即可：

| 参数 | 默认 | 含义 |
|---|---|---|
| `AUTO_START` | `true` | 注入列表页后自动开始运行 |
| `ROTATE_MS` | 10 分钟 | 三个列表间轮换周期 |
| `EMPTY_LIMITS` | `new:1, latest:5, unseen:5` | 各列表连续空刷多少次后判定“无内容” |
| `EMPTY_COOLDOWN_MS` | 5 分钟 | 无内容休眠时长 |
| `GAP_SEC` | 10s | 上一次打开话题 → 下一次的最小间隔 |
| `ATTEMPT_SCROLL_PX` | 800px | 每次进话题下滑的固定距离（读一段就走） |
| `DOT_WAIT_MS` | 8s | 回列表后等待蓝点消失的最长时间 |
| `FALLBACK_HOLD_MS` | 10s | 打开话题后到点强制关标签回列表的兜底时间 |
| `LOAD_TIMEOUT_MS` | 20s | 帖子内容加载等待上限 |
| `READY_STABLE_MS` | 700ms | 帖子数连续稳定多久视为“数据加载完” |
| `STEP_MIN/MAX` | 160/380px | 拟人滚动单步长度区间 |
| `DWELL_MIN/MAX` | 2.2s/3.5s | 加载完后的前台停留时长（阅读心跳上报用） |

## 演进历程（由简单到复杂多轮迭代）

- **v0.1~v0.4（初版）**：列表页+话题页双角色协作（localStorage 令牌），刷 `/latest`，记录已访问话题，滑到底部增量加载。期间修复：注入日志前置 TDZ 崩溃（0.4.1）；列表 URL 改 `/unseen`（0.4）。
- **v0.5**：改为只处理带“未读蓝点”（`tr.unseen-topic`，等价 `.topic-post-badges .new-topic`）的话题，三列表（latest/new/unseen）每 20 分钟轮换，前台切到话题标签阅读后回列表等蓝点消失。
- **v0.6**：修复话题页空耗 44s（worker 异常未清令牌+后台节流），加 `FALLBACK_HOLD_MS=10s` 兜底、worker try/finally、缩短停留。
- **v0.7**：轮换改 10 分钟；开话题前把候选行滚到视口正中。
- **v0.8/0.8.1**：空刷计数切换；改为仅 `/new` 生效。
- **v0.9**：轮换 URL 中 new 用 `https://linux.do/new`；“待阅”判据扩展 `.unread-posts`（新回复徽章）；各列表空刷阈值 new=1、其余 3。
- **v0.10.0**：阈值改 new=1、其余 5；触发后进入“无内容休眠”——扫描暂停、面板显示橙色“无内容休眠 mm:ss”倒计时 5 分钟；按钮变“取消休眠”可手动立即恢复；到期自动切换列表。
- **v0.11.0**：同一话题每轮只进一次、不重复进入，未消失的交给列表循环（去掉对同一话题的多次重试）。
- **v0.11.1**：话题页由“滚到底读完（含懒加载）”回退为“下滑固定距离读一段”；确认“读到底”指话题列表读完即切下一个 URL，而非话题内容滚到底。
- **v0.11.2（当前）**：修复“没刷完回复的话题被反复进入”——读一段后即加入本会话已处理集合，本次 url 会话内不再进入；切下一个 url 后清空再处理。

## 技术要点 / 限制
- `GM_openInTab` 前台/后台标签配合；
- 主动切回主标签不可行（浏览器限制），只能靠关闭话题标签回退；
- iframe 方案因反嵌入被否。
